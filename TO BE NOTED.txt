STATION MODULE DATA — FUTURE FIELDS
=====================================
The following fields are available in station module macro XMLs and should be
extracted when station economy/crew features are implemented:

  workforce max (production modules)
    XML path: properties/workforce[@max]
    Meaning:  Maximum number of workers the module can employ.

  workforce capacity + race (habitation modules)
    XML path: properties/workforce[@capacity] and properties/workforce[@race]
    Meaning:  How many workers the module can house and which race they are.

These are NOT currently extracted by generate_station_stats.py. Add them to
Pass 1 of that script when station crew/economy data is needed.


=====================================

Based on the full read of the file, here are the major ones:

**1. SQLite as a persistent cache**
The C# app loads wares, factions, and map defaults once and stores them in a database. On subsequent runs it only re-imports the save file, not the static game data. X4 Foresight re-scans everything from scratch every single time.

**2. Completed trade history, not just active orders** done

**3. Reads game CAT archives directly**
`ContentExtractor` pulls `libraries/wares.xml`, `libraries/factions.xml`, and `libraries/mapdefaults.xml` straight from X4's packed archives. X4 Foresight requires the user to manually extract `0001-l044.xml` with XRCatTool. The C# app has zero manual setup.

**4. Authoritative zone → sector mapping** done

**5. Fleet subordinate hierarchy** - DO THIS.
It tracks `subordinate` relationships with group assignments (e.g. which wing a ship belongs to under which commander). X4 Foresight groups ships by sector but doesn't model the formal commander → subordinate tree.
To expand on this, a demonstration of what ships are doing in a visual manner, or even in a more defined manner on the 'ship card' would be good.

**6. Galaxy topology** - Sort of done. Needs defining super highways ect

**7. Destroyed/removed objects** - Done in CLI

**8. Everything is SQL-queryable** - Needs expanding
Any data relationship can be explored with an ad-hoc query. X4 Foresight's JSON export is a fixed schema — you can only answer questions the export was designed for.
